如何写一条好的 commit message

第一步，先确认这次提交只做一件事。如果一次改动里混入了功能开发和格式调整，先用 git add -p 把改动拆开，分多次提交。混合提交会让后续 review 和回滚变得困难。

第二步，写标题行。标题行控制在 50 个字符以内，使用祈使语气，比如 "fix login redirect" 而不是 "fixed login redirect"。标题行不要以句号结尾，也不要写 "update"、"fix bug" 这类没有信息量的词。

第三步，空一行再写正文。正文用来说明为什么要做这个改动，而不是重复改了什么。改动内容可以从 diff 里看到，改动动机看不到，所以正文应该回答"为什么"。正文每行建议不超过 72 个字符。

第四步，如果有对应的 issue，在正文末尾引用，例如 "Closes #142"。这样合并后 issue 会自动关闭。

第五步，提交前跑一遍测试和格式化工具。这个习惯比写得多漂亮更重要，因为一条信息完整的 commit 如果带着失败的测试，价值仍然是零。

常见错误：把提交说明写成变更清单；一次提交包含多个不相关的修复；标题使用过去式；正文完全没有解释动机。
