# make-knowledge-cards

一个用于支持 Agent Skills 的客户端（如 CodeBuddy）的开源 Skill：把**用户粘贴的文章**或**本地 Markdown/TXT 文件**，转换成 **5–8 张知识卡片**。

## 1. 项目解决什么问题

读到一篇有价值的文章后，真正的麻烦往往不在"读完"，而在"留不住"：长文要点散落在段落里，复习时只能重读全文；随手做成笔记又容易变成原文缩写，看不出哪几句才是关键。

这个 Skill 做的是**忠实的知识压缩**：读完原文后只搬运真正重要的知识点，一张卡讲一件事，用自己的话写清结论、机制和边界，并附上例子或自测题，让内容可以被快速复习、自我检验。它明确拒绝两种常见的失败：为了凑数量而拆句注水，以及为了讲清楚而编造原文没有的信息。

## 2. 主要功能

- **两种输入**：直接粘贴的文本；本地 `.md` / `.markdown` / `.txt` 文件（先读全文再成卡）。
- **固定四段输出**：每张卡片包含 `标题`、`核心知识`（一句话结论）、`简明解释`（2–4 句，补充条件/机制/边界）、`例子或自测问题`（例子优先取自原文，推演例子会标注）。
- **一张卡一个知识点**：同一知识点只出现一次，重叠的合并，可从多张卡说清的内容才拆分。
- **数量服从信息量**：正常输出 5–8 张；原文撑不起时输出实际能支撑的 1–3 张，并说明原因，不凑数。
- **不编造**：不补背景、数据、人物、结论；数字与实验/统计条件一起搬；原文说"相关"不写成"导致"，作者观点标注为观点。
- **交付自检**：成卡前核对 10 条检查项（去重、可溯源、四段不互相复读、自测题可只用本卡作答等）。
- **文末固定说明**：输出以一行"共 N 张：覆盖了什么；什么没成卡及原因"结尾。
- **可保存到文件**：用户要求保存时，写到指定路径；未指定则写到源文件同目录的 `<源文件名>-知识卡片.md`。

不支持：网页抓取 / URL、PDF、Word、图片扫描件、Anki/APKG 导出、GUI 界面。遇到这类输入，Skill 会说明并请用户改为粘贴纯文本或提供 `.md`/`.txt`。

## 3. 安装方法

无需安装依赖、无需构建，项目中不含脚本，只有一个提示词包，复制目录即可使用。

选择一个作用域，把 `skills/make-knowledge-cards/` 整个目录复制过去：

```bash
# 项目级：只在该仓库生效，可与协作者共享
<你的项目>/.codebuddy/skills/make-knowledge-cards/

# 用户级：本机所有项目可用
~/.codebuddy/skills/make-knowledge-cards/
```

目录内需要保留两个文件：

```
make-knowledge-cards/
├── SKILL.md          # 技能主体（必需）
└── agents/
    └── openai.yaml   # 界面元信息：显示名、简介、默认提示词（可选）
```

安装后确认目录名与 `SKILL.md` 里的 `name: make-knowledge-cards` 一致，客户端才能在合适的时机自动触发。

## 4. 使用方法

复制完成后，在对话里直接提任务即可，不需要输入命令：

```text
把下面这篇做成知识卡片：
（粘贴文章正文）
```

```text
把 notes/redis-persistence.md 转成知识卡片
```

```text
帮我做 6 张复习卡片，重点放在这篇文章的操作步骤上
```

行为说明：

- 只给主题、没给原文时，Skill 会先索取原文，不会自行编内容。
- 要求"更多卡/更少卡"时按其数量执行，但仍守住"一张卡一个知识点、不注水"的底线。
- 要求保存时输出到文件，否则直接在对话中返回 Markdown。

## 5. 输入输出示例

**输入**

```text
把这段转成知识卡片：

深度工作指在无干扰状态下专注进行职业活动，使认知能力达到极限。
这种努力能创造新价值、提升技能且难以复制。相比之下，浮浅工作是
无需太多认知努力的事务性任务，容易被打断，也容易被替代。
```

**输出**

```markdown
### 卡片 1：什么是深度工作

**核心知识**：深度工作是在无干扰状态下把认知能力推到极限的职业活动。

**简明解释**：它的关键在于"无干扰"和"高认知负荷"两个条件同时成立；
这样的努力能创造新价值、提升技能，且难以被复制。

**例子或自测**：自测——把任务称为"深度工作"需要同时满足哪两个条件？
参考答案：无干扰的环境 + 认知能力接近极限。

### 卡片 2：深度工作与浮浅工作的区别

**核心知识**：区别在于认知负荷高低，以及是否容易被中断和替代。

**简明解释**：浮浅工作是无需太多认知努力的事务性任务，容易被中断；
正因为门槛低，它也更容易被替代。

**例子或自测**：自测——原文把"容易被替代"归因于什么？
参考答案：归因于任务本身认知门槛低、可中断。

共 2 张：仅覆盖"定义"与"两类工作对比"；原文信息量不足 5 张，未凑数。
```

## 项目结构

```
.
├── README.md
├── LICENSE
├── skills/
│   └── make-knowledge-cards/
│       ├── SKILL.md          # 技能主体：适用范围、6 步工作流、硬性约束、示例、边界情况
│       └── agents/
│           └── openai.yaml   # 界面元信息（显示名、简介、默认提示词）
└── tests/
    ├── inputs/               # 4 篇不同类型的测试文章
    └── outputs/              # 对应的卡片产出
```

## 校验

使用 skill-creator 自带的 `quick_validate.py`：

```bash
python -X utf8 quick_validate.py skills/make-knowledge-cards
# Skill is valid!
```

> Windows 下需加 `-X utf8`：脚本按系统默认编码（GBK）读取中文 `SKILL.md`，否则会解码失败。
