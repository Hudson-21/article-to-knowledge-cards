# 知识卡片生成

## 概述

把一段文章（用户粘贴的文本，或用户指定的本地 Markdown/TXT 文件）压缩成 5–8 张知识卡片。每张卡片只承载一个知识点，包含标题、核心知识、简明解释、例子或自测问题。核心原则是**忠实压缩**：只搬运原文真正重要的信息，不编造、不注水、不凑数。

## 适用范围

支持：

- 用户直接粘贴的文本
- 本地 `.md` / `.markdown` / `.txt` 文件（用读取文件的工具先读出全文）

不支持，遇到时直接说明并给出替代方案，不要勉强处理：

- 网页抓取 / URL 链接 → 请用户粘贴正文
- PDF、Word、图片、扫描件 → 请用户提供文本或转换后的 Markdown
- Anki 导出、APKG、GUI/网页界面

## 工作流程

### 第 1 步：获取原文

- 用户只给了主题、没给原文时，先请其粘贴文本或给出文件路径，不要凭标题自行生成内容。
- 粘贴文本：直接使用，不要求补充材料。
- 文件输入：先完整读取文件。`.md` 忽略 YAML frontmatter、图片链接、纯排版符号；`.txt` 若无段落结构，先按空行或话题自行切分。
- 原文明显不完整（截断、只有标题、只有几句口号）时，先说明情况，再按"边界情况"处理，不要靠常识补全。

### 第 2 步：通读全文，抽取候选知识点

先完整读完再动笔，不要边读边写卡。逐段自问：**这一段里，读者如果只带走一句话，是哪一句？**

值得成卡的内容：

- 定义、术语、关键区分（A 与 B 的差别）
- 原理、机制、因果解释（为什么会这样）
- 可操作的步骤、规则、清单、判断标准
- 反直觉的结论、常见误区、易错点
- 带条件的结论（有阈值、前提、适用范围的信息必须连同条件一起搬）

不值得成卡的内容：

- 开场铺垫、作者个人经历、情绪与修辞
- 过渡句、重复表述、广告、免责声明、目录式罗列
- 只有结论没有支撑、且信息量极低的泛泛之谈

### 第 3 步：去重、排序、定数量

1. 合并同义或相互包含的知识点（同一件事只留一张卡）。
2. 检查覆盖面：卡片要覆盖原文的主要部分，不能全挤在开头几段，也不能只留下结论而丢掉关键论据。
3. 用"读者只记住三件事会是哪三件"的标准排序，重要的放前面。
4. 取 5–8 张。原文信息量撑不起 5 张时，**输出实际能支撑的数量（可少至 1–3 张）**，并用一句话说明为什么更少。绝不允许为凑数拆句、凑字数或复述同一知识点。
5. 原文信息量远超 8 张时，不要扩到 9 张以上；继续合并，保证每张卡仍聚焦单一知识点。

### 第 4 步：逐张写卡片

每张卡片固定四段，缺一不可：

```markdown
### 卡片 N：标题

**核心知识**：一句话结论，不超过 50 字，独立可读。

**简明解释**：2–4 句，说明它是什么、为什么成立、怎么用。只用原文已有的信息。

**例子或自测**：二选一。
- 例子：优先用原文自带的案例，可压缩但不可改事实；原文无例子时，可用原文事实直接推演，并标注"推演例子"。
- 自测：一个能且只能用本卡内容回答的问题，附参考答案。
```

四段各司其职，不要互相复读：

- **标题**：20 字以内，名词短语或判断句，读完就知道这张卡讲什么；不复用"概述""要点一"。
- **核心知识**：只写结论，读者不看解释也懂；不写背景、不写"本文介绍"。
- **简明解释**：补充结论成立的条件、机制或边界，**不要重复核心知识的句子**。涉及数字、实验、阈值时必须连条件一起写（例如"小睡 90 分钟""一晚 4 小时"）。
- **例子或自测**：例子优先来自原文；自测的答案必须能直接从本卡内容推出，而不是靠读者常识。

### 第 5 步：交付前自检

逐条核对，不通过就改，不要直接交付：

- [ ] 每张卡片只有一个知识点，标题之间不重叠
- [ ] 没有任何两张卡在讲同一件事
- [ ] 每个事实、数字、结论都能在原文中找到出处
- [ ] 数字与实验/统计条件同时出现，没有被单独摘出
- [ ] 没有原文之外的因果、数据、案例、评价
- [ ] 解释没有复读核心知识，而是提供了新信息（机制、条件或边界）
- [ ] 每道自测题都能只用本卡内容作答
- [ ] 卡片数量在 5–8 之间；更少时已说明原因
- [ ] 标题具体可判断，不出现"概述""总结""其他"这类空标题
- [ ] 解释是原文的压缩，不是原文的扩写

### 第 6 步：输出

- 默认直接在对话中输出 Markdown。
- 用户要求保存时，写到用户指定路径；未指定则写到源文件同目录，命名为 `<源文件名>-知识卡片.md`。
- 结尾固定用一行说明，格式为"共 N 张：覆盖了什么；什么没成卡及原因"，不必写成长篇复盘。

## 硬性约束

1. **不编造**：不补充原文没有的背景、数据、人物、结论。原文含糊就写含糊，必要时在解释里注明"原文未展开"。
2. **不重复**：同一知识点只出现一次，即使它在原文多处出现。
3. **不凑数**：数量服从原文信息量，不是服从 5–8 这个区间。
4. **不失真**：压缩时保留限定条件（"在某些情况下""仅对 X 有效"），删掉限定条件等于制造错误。
5. **一张一知识点**：如果一张卡需要两个标题才能说清，就拆成两张；但拆分不得把一句话切成两张卡。
6. **自足可答**：自测题必须能只用本卡内容作答；需要原文其他部分或读者常识才能答的题，换掉。
7. **保留证据强度**：原文说"相关"就不要写成"导致"，原文是作者观点就标注"作者认为"，原文说"证据有限"就保留这句限定。

## 常见失误

| 失误 | 表现 | 修正 |
| --- | --- | --- |
| 复述原文 | 卡片等于段落缩写 | 提炼成结论 + 机制，删掉铺垫 |
| 知识点重叠 | 卡片 2 和卡片 5 都在讲同一原则 | 合并，或改为该原则的不同侧面 |
| 概念漂移 | 从原文的一点引申出原文没有的建议 | 删除引申，回到原文语句 |
| 强行成卡 | 把"注意安全"这类空话做成一张卡 | 舍弃，或并入相关卡片 |
| 数量注水 | 一张卡拆成"定义卡 + 意义卡 + 应用卡" | 合并为一张，四段式写清即可 |
| 四段复读 | 核心知识与简明解释是同一句话换了说法 | 解释改为补充条件、机制或边界 |
| 越界作答 | 自测题要靠常识或其他卡片才能答 | 改问本卡内能直接查到的事实 |

## 示例

原文（节选）："深度工作指在无干扰状态下专注进行职业活动，使认知能力达到极限。这种努力能创造新价值、提升技能且难以复制。相比之下，浮浅工作是无需太多认知努力的事务性任务，容易被打断，也容易被替代。"

```markdown
### 卡片 1：什么是深度工作

**核心知识**：深度工作是在无干扰状态下把认知能力推到极限的职业活动。

**简明解释**：它的关键在于"无干扰"和"高认知负荷"两个条件同时成立；这样的努力能创造新价值、提升技能，且难以被复制。

**例子或自测**：自测——把任务称为"深度工作"需要同时满足哪两个条件？参考答案：无干扰的环境 + 认知能力接近极限。

### 卡片 2：深度工作与浮浅工作的区别

**核心知识**：区别在于认知负荷高低，以及是否容易被中断和替代。

**简明解释**：浮浅工作是无需太多认知努力的事务性任务，容易被中断；正因为门槛低，它也更容易被替代。

**例子或自测**：原文把"容易被替代"归因于什么？参考答案：归因于任务本身认知门槛低、可中断。
```

## 边界情况

- **原文过短或只有单一观点**：输出 1–3 张，明确说明"原文信息量仅支撑 N 张"。
- **原文是清单/要点罗列**：按主题聚合成 3–5 个知识点，不要一条一行照搬。
- **议论文/观点文**：卡片呈现"作者主张 + 原文给出的理由"，按"主张 → 机制/反驳 → 方案 → 证据边界"排序，并标明这是观点而非定论。
- **教程/操作类**：步骤卡保留顺序与前置条件，必要时在标题里带序号。
- **代码密集型**：只卡片化设计意图、关键接口、常见坑，不复述代码本身。
- **多语言混排**：卡片语言跟随原文主体语言；术语可保留原词并给中文解释。
- **用户要求"更多卡"/"更少卡"**：按其数量执行，但仍守住"一张一知识点、不注水"的底线，数量超出原文支撑时直接说明。
